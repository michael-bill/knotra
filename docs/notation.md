# Нотация Knotra

Статус: полный проект контракта v1 для ревью, 30 сентября 2026 года. Прежнее описание принципов конкретизировано в нормативной спецификации. Движок ещё не реализован; язык согласуется до его реализации.

Основной результат — контракт для авторов пайплайнов и исполнителя: точные поля YAML, типы данных, правила ссылок, состояния и наблюдаемое поведение. Контрольные документы служат проверками, а не определением языка через отдельный пример.

| Документ | Что определяет |
| --- | --- |
| [Контракт v1](notation/v1.md) | Полный справочник Pipeline, портов, Binding, scopes и всех девяти типов кубиков |
| [Семантика исполнения](notation/execution.md) | Готовность, skip/null/error, циклы, ABI, результаты, retry, timeout, отмена и восстановление |
| [EngineProfile](notation/engine-profile.md) | Модели, MCP, секреты, sandbox, capabilities и ограничения прав |
| [Проверка и пакет](notation/validation.md) | YAML/CEL/DataSchema, файлы, лимиты, этапы валидации и диагностика |
| [JSON Schema](../schemas/knotra-v1.schema.json) | Структурная проверка обоих видов документов |
| [Контрольные YAML](../contracts/v1/fixtures/README.md) | Положительные/отрицательные случаи и проверка схемы |

Контракт включает `llm`, `agent`, `code`, `tool`, `switch`, `human`, `foreach`, `loop` и `pipeline`. Он отделяет переносимое описание процесса от доверенной конфигурации движка и JSON-значения от файловых артефактов.

Проект v1 требует совместного соблюдения JSON Schema и текстовой семантики. Схема сама не проверяет существование ссылок, DAG, CEL, permissions, безопасные повторы или поведение внешних систем. Соответствующие требования уже определены в спецификации; их исполнение предстоит реализовать и проверить.

После ревью и согласования этот контракт становится основанием для разработки компилятора и runtime. Поэтапная реализация возможностей отражается в [дорожной карте](roadmap.md); неподдерживаемые возможности отклоняются до запуска.
