# Контракт нотации Knotra v1

Реализация контракта находится в `internal/contract`, `internal/engine` и `internal/adapters`. Настройка исполняемой версии описана в [руководстве запуска](../running.md); нижеследующие правила сохраняют силу независимо от исторического статуса документа.

Статус: полный проект контракта для ревью, 30 сентября 2026 года. Этот документ описывает язык, который предстоит реализовать. Наличие поля в контракте не означает, что движок уже существует или поддерживает его. После согласования контракта реализация может идти поэтапно; неподдерживаемые конструкции должны отклоняться до запуска.

Контракт состоит из четырёх нормативных документов:

- Этот документ: структура, типы, привязки, области видимости и все виды кубиков.
- [Исполнение](execution.md): планирование, результаты, состояния, повторы, файлы и восстановление.
- [Профиль движка](engine-profile.md): подключения, sandbox, секреты и права.
- [Проверка](validation.md): пакет, YAML, CEL, проверки и диагностика.

[JSON Schema](../../schemas/knotra-v1.schema.json) задаёт структурную часть контракта в Draft 2020-12. Текст задаёт дополнительные семантические ограничения. Документ допустим, только если выполнены обе части. Несогласованность схемы и текста считается дефектом контракта; реализация не должна выбирать удобное толкование молча. [Контрольные документы](../../contracts/v1/fixtures/README.md) проверяют контракт, но не заменяют его.

Слова «обязательно», «запрещено», «должен» обозначают требования. «По умолчанию» означает действие нормализатора Knotra: стандартный валидатор JSON Schema самостоятельно ничего не дописывает.

## 1. Два вида документов

Корень содержит ровно четыре обязательных поля:

| Поле | Тип и значение |
| --- | --- |
| `apiVersion` | Строка `knotra/v1` |
| `kind` | `Pipeline` или `EngineProfile` |
| `metadata` | Метаданные ниже |
| `spec` | Спецификация выбранного вида |

`Pipeline` — переносимое описание процесса. `EngineProfile` — доверенная конфигурация конкретного движка. Профиль выбирает оператор движка вне пакета пайплайна; файл профиля в присланном пакете не даёт процессу дополнительных прав.

В `metadata` обязательно `name`: от 1 до 63 ASCII-символов, первая строчная латинская буква, далее строчные буквы, цифры и дефис. Необязательны непустые строки `title`, `description`, `version` и `labels`, объект строковых значений. `metadata.version` — версия авторского процесса, не версия языка; она не определяет идентичность пакета.

Все служебные объекты закрыты: неизвестное поле является ошибкой. Произвольные ключи разрешены только в явно объявленных таблицах, пользовательских JSON-значениях, данных схем, метках и параметрах адаптеров. Порядок ключей объекта не влияет на исполнение. Порядок списков имеет значение.

## 2. Общие типы

| Тип | Правило |
| --- | --- |
| `Identifier` | Полное совпадение с `[a-z][a-z0-9_]{0,63}`. Имена кубиков, портов, состояний, ресурсов, схем |
| `ToolName` | 1–128 ASCII-символов из `A–Z`, `a–z`, `0–9`, `_`, `-`, `.`; регистр значим |
| `Duration` | Положительное целое без начальных нулей + одна единица `ms`, `s`, `m`, `h`. Например, `500ms`, `30m`; `0s`, `1h30m` запрещены. Значение не более 365 суток |
| `Path` | Нормализованный относительный POSIX-путь длиной 1–1024 символа. Без пустых сегментов, `.`/`..`, обратного слеша, управляющих символов U+0000–001F/U+007F, начального `/` или Windows drive prefix |
| `Json` | `null`, boolean, строка Unicode, число, массив или объект со строковыми ключами. Только конечные числа; числовой профиль — в [проверке](validation.md) |
| `Argv` | Непустой массив строк. Первый элемент непустой; следующие могут быть пустыми. NUL запрещён во всех элементах. Интерполяция и неявный shell отсутствуют |
| `TextSource` | Ровно `{text: непустая строка}` либо `{file: Path}`. Файл — непустой UTF-8 текст из пакета |

Файл источника читается относительно корня пакета, а не текущего YAML. Пути `mount` и `collect.path` относятся к рабочей директории sandbox; они используют тот же лексический тип `Path`, но другой корень.

## 3. Pipeline.spec

| Поле | Обязательно | Смысл / отсутствие |
| --- | --- | --- |
| `files` | Нет | Уникальный список включённых путей пакета; по умолчанию `[]` |
| `schemas` | Нет | Таблица `Identifier → SchemaSource`; по умолчанию `{}` |
| `models` | Нет | Таблица моделей; по умолчанию `{}` |
| `mcp` | Нет | Таблица MCP-подключений; по умолчанию `{}` |
| `sandboxes` | Нет | Таблица профилей sandbox; по умолчанию `{}` |
| `secrets` | Нет | Таблица ссылок на секреты; по умолчанию `{}` |
| `defaults` | Нет | Общие настройки исполнения и инструментов |
| `limits` | Нет | Более строгие лимиты в пределах профиля движка |
| `inputs` | Нет | Таблица входных портов `InputPort`; по умолчанию `{}` |
| `nodes` | Да | Непустая таблица `Identifier → Node` |
| `outputs` | Да | Непустая таблица экспортируемых портов `Export` |

Идентификаторы уникальны внутри своей таблицы. Одинаковое имя модели и входа допустимо: у них разные пространства имён. Ссылки чувствительны к регистру. Кубики не вызываются в порядке записи: движок строит граф зависимостей.

### Ресурсы

| Таблица | Поля записи |
| --- | --- |
| `models` | Обязательное `connection` — имя подключения из `EngineProfile.spec.models`. Необязательные `model` — непустое переопределение модели, `parameters` — объект параметров адаптера, `requires` — уникальный список `toolCalling`, `structuredOutput`, `imageInput` |
| `mcp` | Обязательное `connection` — имя из `EngineProfile.spec.mcp`. `session: node` по умолчанию либо `run` |
| `sandboxes` | Обязательное `profile` — имя из `EngineProfile.spec.sandboxes` |
| `secrets` | Обязательное `ref` — имя из `EngineProfile.spec.secrets` |

В самих кубиках используются локальные имена этих ресурсов. Исключение — `pipeline.permissions`, где используются имена профиля движка, чтобы переименование локального alias не обходило права.

`parameters` объединяются с параметрами подключения по верхнему уровню ключей: локальное значение целиком заменяет значение этого ключа. Допустимые ключи и типы объявляет зарегистрированный адаптер; произвольный транспортный payload сюда передавать нельзя. Неизвестные параметры и неподдерживаемые возможности — ошибка подготовки. Молчаливого выбора другой модели или провайдера в v1 нет.

### Defaults и limits

`defaults` содержит только необязательные `execution` и `tools`. Настройки `execution` наследуются кубиками всех вложенных Graph текущего Pipeline. В вызываемом Pipeline действуют его собственные defaults; ограничения родителя продолжают действовать.

`limits` содержит положительные `maxConcurrentNodes`, `maxNodeInstances`, `maxModelCalls`, `maxToolCalls` и `timeout: Duration`. Каждый отсутствующий лимит наследуется от действующего профиля/родителя. Увеличение разрешённого лимита является ошибкой. `maxNodeInstances` включает каждый экземпляр кубика, в том числе внутри итераций; попытки не создают новый экземпляр. Семантика счётчиков и времени описана в [исполнении](execution.md).

`defaults.tools` содержит `mcp: {локальный_server: [ToolName, ...]}` и `sandbox: [files.read, files.write, process.exec]`. По умолчанию обе таблицы/списки пусты. Список имён у одного MCP-сервера непустой и без повторов. Эти общие разрешения получают только `agent`-кубики. Они не запускают инструменты автоматически.

## 4. Схемы данных и порты

JSON и файловый артефакт — разные категории значений. Объект, похожий на описание файла, не становится артефактом. Для каждого порта указывается ровно одно из:

- `schema: DataSchema` — встроенная схема JSON;
- `schemaRef: Identifier` — имя в `spec.schemas` текущего Pipeline;
- `artifact: {mediaTypes: [...], collection?: false}` — файловый контракт.

`SchemaSource` — `DataSchema` либо `{file: Path}` с JSON/YAML-схемой из пакета. Все Graph внутри Pipeline используют его реестр схем. Подпайплайн имеет свой реестр.

### DataSchema

Поддерживается закрытый профиль JSON Schema Draft 2020-12: boolean-схемы `true`/`false` и объекты со следующими ключами:

- `$schema`, `$ref`, `$defs`, `$comment`, `title`, `description`;
- `type`, `const`, `enum`, `default`, `examples`;
- `properties`, `patternProperties`, `additionalProperties`, `propertyNames`, `required`, `minProperties`, `maxProperties`, `dependentRequired`, `dependentSchemas`;
- `items`, `prefixItems`, `contains`, `minContains`, `maxContains`, `minItems`, `maxItems`, `uniqueItems`;
- `minLength`, `maxLength`, `pattern`;
- `minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`, `multipleOf`;
- `allOf`, `anyOf`, `oneOf`, `not`, `if`, `then`, `else`.

Типы и смысл ключей следуют стандарту. `$schema`, если указан, равен `https://json-schema.org/draft/2020-12/schema`. `$ref` разрешён только как локальный JSON Pointer (`#` или `#/...`) внутри самостоятельного корня DataSchema. Внешние ссылки, `$id`, якоря, динамические ссылки, `format` и неизвестные расширения запрещены. Циклические цепочки `$ref` запрещены в v1. Регулярные выражения ограничены переносимым подмножеством RE2/ECMA-262, определённым в [проверке](validation.md).

Неуказанное `additionalProperties` означает `true`, как в стандарте. Закрытость служебных объектов Knotra не меняет правила пользовательской схемы. `default` внутри DataSchema — аннотация, не вставка значений. Knotra всегда самостоятельно проверяет конечный результат модели, даже если API провайдера обещает structured output.

### Разновидности портов

Общее необязательное поле `description` — непустая строка.

| Место | Дополнительные поля |
| --- | --- |
| `Pipeline.inputs`, `Graph.inputs` (`InputPort`) | `required: true` по умолчанию; необязательный `default: Json`, только для JSON |
| `Node.inputs` (`NodeInput`) | Обязательный `bind: Binding`; `required: true` по умолчанию; `mount: Path` обязателен для артефакта в agent/code и запрещён в других случаях |
| JSON-выход llm/agent/code/human (`JsonOutput`) | Только `schema`/`schemaRef`; `required: true` по умолчанию |
| Файловый выход agent/code (`FileOutput`) | Обязательные `artifact` и `collect: {path: Path, mediaType: строка}`. Только одиночный файл: `collection` отсутствует или `false`. Выход всегда обязательный |
| `Pipeline.outputs`, `Graph.outputs` (`Export`) | Обязательный `bind`; `required: true` по умолчанию |
| `loop.state` (`LoopState`) | Обязательные `initial: Binding`, `next: Binding`; без `required`, `default`, `mount` |

Значение `InputPort.default` проверяется по схеме при подготовке и подставляется только при отсутствии ключа во входных данных. Затем проверяется `required`. Явный `null` не заменяется default. Входные и выходные объекты портов не могут содержать неизвестные имена. Внутренние поля пользовательского JSON регулирует его DataSchema.

`artifact.mediaTypes` — непустой уникальный список точных MIME-типов без параметров и wildcard. `collection: false` означает один файл, `true` — упорядоченный список файлов, допускающий пустой список. Все члены коллекции соответствуют указанным типам. `collect.mediaType` должен входить в `mediaTypes`; расширение файла не определяет тип автоматически.

Артефакт существует только как зарегистрированный движком неизменяемый handle, привязанный к байтам, размеру и SHA-256. На вход запуска он поступает через загрузку/разрешение движком; точный сетевой endpoint будет частью API. Между кубиками он передаётся через `from` или `coalesce` таких ссылок. Вычисления `expr`/`value`, JSON Pointer и преобразование JSON в handle для артефактных привязок запрещены.

## 5. Binding и области видимости

`Binding` — объект ровно одного из четырёх видов:

| Форма | Значение |
| --- | --- |
| `{value: Json}` | Литерал JSON без интерполяции |
| `{from: ссылка, path?: JSONPointer}` | Значение порта; необязательный RFC 6901 Pointer выбирает часть JSON |
| `{expr: строка CEL}` | Вычисление с сохранением JSON-типа результата |
| `{coalesce: [Binding, Binding, ...]}` | Первый присутствующий результат по порядку; минимум два варианта |

Разрешённые ссылки: `inputs.<port>`, `nodes.<node>.outputs.<port>`, `args.<port>`, `state.<name>`, `iteration.item`, `iteration.index`, `body.outputs.<port>`. Список синтаксических форм не означает, что все они доступны в каждом месте.

| Место вычисления | Доступный контекст |
| --- | --- |
| `Node.inputs.*.bind` | `inputs`, `nodes` текущего Graph |
| `Node.when` | `inputs`, `nodes`, уже разрешённые `args` текущего кубика |
| `Graph.outputs.*.bind`, `Pipeline.outputs.*.bind` | `inputs`, `nodes` текущего Graph |
| `tool.arguments`, `switch.cases[].when` | Только `args` |
| `foreach.with.*` | `args`, `iteration.item`, `iteration.index` |
| `loop.state.*.initial` | Только `args` |
| `loop.with.*` | `args`, текущее `state`, `iteration.index` |
| `loop.until`, `loop.state.*.next` | `args`, текущее `state`, `iteration.index`, `body.outputs` завершённого тела |

`inputs` — входы текущего Graph, `args` — входы текущего кубика, `nodes` — его соседи. Тело foreach/loop видит только собственные входы и кубики; наружные значения передаются через `with`. История модели, файлы соседей и секреты в CEL не попадают. Итерационный индекс начинается с нуля.

В ссылках на узлы и порты имена должны быть статически известны. CEL допускает `nodes.review.outputs.score`; вычисляемые обращения вроде `nodes[args.node]` запрещены. Обращения внутри пользовательских JSON-значений могут быть динамическими. Зависимости извлекаются из разобранного AST, включая обе ветви тернарного выражения и все варианты coalesce.

Отсутствие отличается от `null`: `coalesce` выбирает `null`, если он присутствует. Все источники должны завершиться; ошибка источника не является резервным вариантом. Нельзя скрыть пропущенный выход через `has(nodes.x.outputs.y)` или короткое замыкание CEL. Для альтернативных источников используется `coalesce`; для необязательного входа — `required: false`. Полные правила missing/skip/error приведены в [исполнении](execution.md).

JSON Pointer: пустая строка выбирает целое значение; `/a~1b` выбирает ключ `a/b`, `/a~0b` — `a~b`. Индекс массива — `0` либо десятичное число без ведущего нуля; `-` не означает последний/новый элемент. Отсутствующий путь даёт missing; некорректный escape — ошибку подготовки.

## 6. Общие поля Node

Каждый кубик имеет обязательный `type` и поля своего типа. Его имя — ключ в `nodes`.

| Поле | Правило |
| --- | --- |
| `description` | Необязательная непустая строка |
| `inputs` | Таблица NodeInput, по умолчанию `{}` |
| `needs` | Уникальные имена соседних кубиков, по умолчанию `[]`; зависимость успешного завершения без передачи данных |
| `when` | CEL с boolean-результатом; отсутствие равно `true`; проверяется после разрешения входов |
| `execution` | Необязательные `timeout`, `retry`, `onUnknownOutcome` |

`execution` объединяется с defaults по полям, включая поля объекта `retry`; прочие объекты языка автоматически рекурсивно не объединяются. `retry.maxAttempts` обязателен внутри явно записанного `retry`, 1–100, включая первую попытку. По умолчанию одна попытка; `backoff` по умолчанию `1s`, постоянная задержка между допустимыми повторами, без экспоненциального роста. `onUnknownOutcome: pause` по умолчанию, альтернатива `fail`.

Эффективный `retry.maxAttempts` должен быть 1 у switch/human/foreach/loop/pipeline. В частности, общий defaults с большим количеством попыток требует переопределения у этих типов. Retry не даёт разрешения повторять внешние эффекты: [исполнение](execution.md) задаёт допустимость каждой попытки.

Если `execution.timeout` не задан явно или через defaults: для llm/agent/code/tool — `30m`, для human — `24h`, для switch — `1m`, для foreach/loop/pipeline — оставшееся время родительского запуска. Локальный таймаут ограничен оставшимся временем предков. Он охватывает попытки и задержки, начиная с готовности кубика к исполнению.

## 7. Все виды кубиков

### llm

Обязательны `outputs: {port: JsonOutput, ...}` и `llm: {model, prompt}`; необязательны `llm.instructions`. `model` — локальный alias, `prompt` и `instructions` — TextSource. Одна логическая генерация результата, без инструментов и sandbox. Входы только JSON. Ответ — объект по именам выходных портов; произвольный текст вместо JSON считается ошибкой результата.

Провайдер может выполнять несколько транспортных попыток только по политике повторов; каждый фактический запрос списывает бюджет. Отдельного неограниченного цикла исправления JSON нет. Скрытые транспортные повторы внутри попытки запрещены; сбой запроса завершает попытку.

### agent

Обязательны `sandbox`, непустые `outputs`, `agent: {model, prompt, maxSteps}`. Необязательны `agent.instructions`, `env`, `tools`. `maxSteps` — число обращений к модели в одной попытке агента, 1–10000, включая первое; повторные сетевые запросы также ограничены общим `maxModelCalls`.

Агенту выдаются только разрешённые MCP и встроенные инструменты sandbox. `tools` имеет поля `inherit: true` по умолчанию, `mcp`, `sandbox`. При inherit=true локальные grants объединяются с defaults.tools по множествам; false начинает с пустого набора. Итог проверяется по профилю движка и ограничениям предков; лишние права — ошибка, а не молчаливое обрезание.

Завершение выполняется служебным инструментом `knotra.finish` с объектом JSON-выходов; файловые выходы собирает движок. Служебное завершение не требует пользовательского grant и не считается внешним вызовом инструмента. Детали последнего шага и проверки finish — в [исполнении](execution.md). Новый агент не наследует разговор другого кубика.

### code

Обязательны `sandbox`, непустые `outputs`, `code: {command: Argv}`; необязателен `env`. Движок запускает один процесс с указанным argv в sandbox. Первый аргумент разрешается по правилам ОС/образа; shell используется только если явно указан исполняемым файлом. Пустые аргументы после первого сохраняются. Успех требует exit code 0 и проверки JSON/файловых выходов по [ABI исполнения](execution.md).

`env` у code/agent — таблица имён переменных (`[A-Za-z_][A-Za-z0-9_]*`) в объекты ровно `{value: строка}` либо `{secret: локальный_alias}`. Нет `${ENV}`, неявного чтения `.env` или копирования окружения CLI. Имена `KNOTRA_*` зарезервированы движком.

### tool

Обязательны `tool: {server, name, arguments}` и `outputs: {result: JsonOutput}`. Другие имена выходов запрещены. `server` — локальный MCP alias, `name` — точное имя инструмента, `arguments` — Binding, вычисляемый в args и возвращающий JSON-объект.

`tool.response` по умолчанию `structured`: значение result — `structuredContent` успешного ответа MCP, отсутствие этого поля является ошибкой, без автоматического разбора текста. В режиме `content` result — массив MCP content blocks как JSON. Успешный JSON проверяется по объявленной схеме result; `isError: true` означает ошибку независимо от содержимого. Отдельный sandbox этого кубика не создаётся; stdio-сервер использует своё окружение из EngineProfile. MCP resources/prompts и sampling не предоставляются как самостоятельные операции языка v1.

### switch

Обязателен `switch: {cases, default}`. `cases` — непустой упорядоченный список `{name: Identifier, when: CEL}`. Условия видят args и возвращают boolean. Все имена и default попарно различны. Выбирается первый true, иначе default.

Кубик имеет один производный выход `route`: строка из множества имён cases и default. Поле `outputs` записывать нельзя. Имена веток не запускают одноимённые кубики автоматически: последующие кубики читают route и используют `when`.

### human

Обязательны `human: {prompt: TextSource}` и непустые JSON-`outputs`. Движок сохраняет запрос, текст, контекст входов и схему ответа и ждёт ответ по идентификатору запроса. Ответ — объект по именам выходов. Невалидный ответ отклоняется, запрос остаётся открытым до таймаута/отмены; первый валидный ответ применяется один раз. UI ответа и аутентификация отвечающего — часть будущего API/CLI. Промпт не является автоматическим разрешением действия.

### foreach

Обязателен `foreach: {over, concurrency, with, body}`. `over` — имя объявленного входа самого кубика, имеющего JSON-массив либо коллекцию артефактов. `concurrency` — положительное максимальное число одновременно работающих итераций, в дополнение к глобальному лимиту.

`with` — таблица Binding для входов body; она может быть `{}`. `body` — Graph. Каждая итерация получает собственный Graph и нумеруется в исходном порядке массива. Выходы тела должны быть обязательными. Каждый JSON-выход становится массивом таких значений, одиночный файловый выход — коллекцией. Коллекцию артефактов экспортировать из body foreach запрещено: неявного flatten нет. Производные выходы имеют имена экспортов body, поля `outputs` у foreach нет. Для пустого входа все результаты — пустые массивы/коллекции. Ошибка любой итерации завершает foreach ошибкой.

### loop

Обязателен `loop: {maxIterations, with, body, until}`. Необязательны `state` и `onLimit: fail | return_last` (по умолчанию fail). `maxIterations` — 1–100000 выполнений body. `state` — таблица LoopState; каждое значение инициализируется из args и проверяется по собственному контракту.

Цикл выполняет тело хотя бы один раз. `with` передаёт args/state/index в входы body. После успешного тела проверяется boolean `until`; true завершает цикл. При false на последней разрешённой итерации fail даёт ошибку `ITERATION_LIMIT`, return_last публикует последнее тело с `termination: limit`. Иначе все `next` вычисляются одновременно по старому состоянию и результатам тела, проверяются и заменяют состояние для следующей итерации. При остановке next не вычисляется.

Производные выходы — экспорты последнего body и обязательные `iterations` (целое число выполнений тела) и `termination` (`condition` либо `limit`). Поэтому body не может экспортировать `iterations`/`termination`. Итоговое state само по себе наружу не публикуется: нужное значение экспортируется телом. `outputs` у loop отсутствует.

### pipeline

Обязателен `pipeline: {file: Path, permissions}`. Указанный файл — самостоятельный Pipeline из того же зафиксированного пакета. Узловые inputs становятся входами вызываемого Pipeline; его defaults входов применяются обычным образом. Выходы выводятся из экспортов вызываемого Pipeline; дополнительное поле outputs запрещено.

`permissions` содержит все четыре обязательных поля: `models: [profile_model_id]`, `mcp: {profile_server_id: [ToolName]}`, `sandboxes: [profile_sandbox_id]`, `secrets: [profile_secret_id]`. Пустой список/объект явно ничего не разрешает. Права вызова пересекаются с правами всех предков и не могут их расширять. Разрешение на модель/сервер включает использование его credentials внутри доверенного подключения; `secrets` разрешает отдельную выдачу сырого секрета процессу. Полные правила — в [профиле движка](engine-profile.md).

Рекурсия импортов запрещена, включая циклы через условные ветки. Дочерние запуски разделяют глобальные бюджеты; вызов подпайплайна не обнуляет лимиты.

## 8. Вложенный Graph

Graph содержит только `inputs` (необязательно), `nodes` и `outputs` (обязательные непустые таблицы). Он не объявляет собственные модели, права или defaults и использует ресурсы ближайшего Pipeline. Граф зависимостей в каждой области ацикличен; loop — отдельная ограниченная конструкция, а не разрешение на обратные рёбра.

Ключи `with` должны существовать в body.inputs. Каждый обязательный вход должен иметь binding либо default. Для конкретной итерации missing обрабатывается так же, как отсутствие входа Graph. Все итерации изолированы друг от друга; доступ к результату соседней итерации возможен только после агрегации foreach или через явно переносимое loop.state.

## 9. Промпты и контекст

TextSource — буквальный текст: `${...}`, `{{...}}` и похожие последовательности не имеют специального значения. Для динамического текста автор явно вычисляет JSON-вход через CEL или code. Движок передаёт инструкции, промпт и отдельный типизированный контекст входов с именами портов; данные не становятся инструкциями конкатенацией скрытых шаблонов.

Нормативный контекст имеет форму `{values: {JSON-порты}, artifacts: {файловые-порты}}`; точный descriptor и файловый ABI определены в [исполнении](execution.md). Адаптер должен сохранить разделение системных инструкций, задания и входных данных в пределах возможностей API. Модель llm получает только JSON. Human получает данные и доступные ссылки на входные артефакты. Agent получает собственные входы и пути смонтированных файлов, доступные инструменты, свою историю и схему finish.

## 10. Версии и границы v1

Любое изменение смысла существующей конструкции после утверждения v1 требует новой версии формата. Неизвестная версия отклоняется. Миграция создаёт новое описание; движок не переписывает старый пакет автоматически. Пока документ имеет статус проекта, изменения фиксируются в истории Git, без обещания совместимости черновиков.

В v1 нет произвольных плагинов внутри YAML, удалённых импортов, секретов в выражениях, неограниченных циклов, рекурсивных подпайплайнов, неявной общей памяти, wildcard-разрешений, автоматического fallback модели, catch/compensation-графов и восстановления с произвольной инструкции процесса. Ошибка по умолчанию останавливает соответствующий запуск. Эти границы не препятствуют полноценному описанию всех девяти объявленных конструкций.

Следующий отдельный контракт реализации — API/события/CLI и адаптеры исполнения. Он обязан сохранять семантику этой нотации; сетевые endpoint и детали Temporal не добавляются в пользовательский Pipeline.
